# AI 修图

原生 Kotlin 写的安卓修图 App（Android 8.0+）。常用修图和本地 AI（消除、变清晰、换脸）在手机上完成，不依赖自建服务端；云端 AI（一句话修图、云端消除和换脸、换装）用用户自己的 API Key，默认火山引擎豆包 Seedream（国内直连，新用户有免费额度），也支持 Gemini 和 OpenAI 兼容接口。

## 功能

- **智能增强**（本机）：自动色阶和白平衡（三个通道的黑白点往平均靠 60%，去偏色又不洗掉夕阳的暖色）、偏暗时提亮（正常和偏亮的照片不压暗）、细节清晰度、自然饱和度（肤色不加）、轻微锐化；强度可调，默认 70%
- **美颜**（本机）：磨皮、美白、瘦脸、大眼四项，默认磨皮 50、美白 30。ML Kit 人脸网格找出所有的脸（整张图里找不到时和换脸一样分块找最大的一张）。
  - 磨皮：每个通道做自引导的导向滤波（半径 = 脸宽 / 45），斑点、痘印、毛孔这类小起伏被抹平，五官轮廓留住；满强度也保留一成原图纹理
  - 美白：对数曲线提亮，暗部提得多、亮部几乎不动
  - 只作用在皮肤上：脸部轮廓内、去掉往外扩一圈的眼睛、眉毛、嘴唇，再乘「像不像这张脸的肤色」（脸内色度的均值和离散程度），头发、胡子、背景、衣领都排除在外；美白往脖子、耳朵缓慢淡出，脸和脖子之间不出分界
  - 瘦脸：外轮廓上眼睛到下巴 25%～90% 的点往脸中线推（中段最多、下巴尖不动），各点影响按权重平均；大眼：眼睛中心附近从更靠中心的地方取色。两者合成一个偏移场，只取一次色
  - 半径、力度都按脸宽算，预览图和原图效果一致。拖滑杆只重算混合和变形，滤波、蒙版进工具时算好；多张脸各算各的，裁出的块重叠时只写有变化的像素
- **人像抠图**（本机）：1.0.13 起默认用 MODNet 人像抠图模型（第一次用下载约 12 MB，可以跳过、改用普通抠图），出头发丝级别的透明度；再用小半径导向滤波把边缘贴到真实轮廓，透明度过渡带收到 0.2～0.8（飘动的头发周围那层糊的「雾」换白底时会发灰，当背景去掉），最后做前景颜色估计（blur fusion），把边缘半透明像素里混进去的原背景色减掉，换底时头发周围不留原背景色的光晕。普通抠图是 ML Kit 自拍分割（模型打在包里，不需要 Google Play 服务，输入只有 256×256，发丝会被切掉）加导向滤波。限制：贴着人的背景物体可能被当成人。效果：背景虚化（先把人从背景里填掉再模糊，没有光晕）、背景黑白、透明背景（存 PNG）、白底 / 证件蓝 / 证件红 / 浅灰 / 黑底
- **变清晰**（本机）：Real-ESRGAN 通用小模型（1.0.9 起用我们自己做的 INT8 量化版，1.4 MB，见 `models/README.md`）放大 2 / 4 倍并去模糊、去噪。分块算（块 192、重叠 12，拼接无缝），有进度、可取消；输入不超过 100 万像素、输出不超过可编辑上限。模拟器上 0.94 MP 输入约 100 秒（浮点版每块 2.8 秒；INT8 版正式包每块 0.8 秒，电脑同时满载时 1.5 秒）
- **消除笔**：手指涂抹要去掉的东西（双指缩放移动，可撤销一笔、调笔刷大小）
  - 一键消除（本机）：MI-GAN 补图模型。只把涂抹范围外扩一圈裁出来算；送进模型前先用 push-pull 把洞填成背景色（MI-GAN 的流水线会在洞的边缘混入原像素，不预填的话被去掉的东西会从边上透出来）。32 位手机没有推理库，回到 push-pull 快速填充
  - 云端消除：Gemini 收到的是盖了半透明红色标记的图，OpenAI 收到原图 + 蒙版；返回结果只取涂抹区域（略外扩、羽化）贴回原图，其余像素保持原分辨率
- **AI 修图**（云端）：一句话描述想怎么改，预设有画质增强、老照片修复、去掉路人、换成蓝天、晚霞天空、证件照白底、动漫风格、去除反光，最近用过的描述也在里面。结果尺寸由模型决定（通常长边 1024 左右）
- **换脸**：选一张正脸照片，把它的脸换到当前照片的人物上，保留当前照片的发型、表情、姿势和光线。
  - 高清（默认、本地）：和 FaceFusion 的流程一致。ArcFace 取参考脸的身份特征 → HyperSwap 1c 在目标脸（按 5 个关键点对齐到 256×256）上换成这个身份，按软边方框整块贴回 → GFPGAN 1.4 把整张脸（按 FFHQ 模板对齐到 512×512）修复清楚，和修复前按 8:2 混合贴回。提供脸的人戴眼镜时，身份特征里带着眼镜，换出来的脸会多一副半透明的眼镜框：1.0.13 起默认「去掉眼镜」（把特征在「眼镜方向」上的投影推回不戴眼镜的人的平均，`core/GlassesDirection.kt`，由 `scripts/glasses_direction.py` 在虚构人脸上画眼镜算出），也可以选「保留眼镜」（往这个方向加一点，换出完整的眼镜）。模型第一次用时从 hf-mirror 下载，都放在 Hugging Face 仓库 `Lakes0001/ai-photo-models`：ArcFace INT8 44 MB、HyperSwap 只量化权重的 INT8 202 MB、GFPGAN 只量化权重的 INT8 88 MB（见 `models/README.md`），三个模型先后加载、用完即释放；这两个大模型关掉内存池和内存复用规划，2.5 GB 内存的模拟器上整个流程的进程峰值约 860 MB。**ArcFace 来自 InsightFace，只允许非商业使用；HyperSwap 没有写明模型许可**（GFPGAN 是 Apache 2.0），下载前和面板上都有提示
  - 快速（本地）：ML Kit 人脸网格（468 点）逐三角形变形贴合，不用下载模型。眼睛和嘴两张脸张开程度接近（比例 ≥ 0.75）才一起换，否则保留目标照片自己的；肤色在亮度 + 色度里对齐，再做光照迁移（明暗大轮廓跟目标走）和外轮廓色差修正。整张图找不到脸时再沿长边分三块找（ML Kit 用近距离模型，竖拍照片里脸会被缩得太小）
  - 云端 AI：第一次使用要确认「只用于本人或已获同意的照片」；服务按自己的安全规则拒绝时，原样显示它给的原因
- **换装**（云端）：选一张衣服的照片照着换，或者点预设（西装、职业装、婚纱、汉服、旗袍、晚礼服、休闲装、运动装、校服、冬装）、自己写想穿什么
- 换脸、带参考照的换装是两张图一起发给模型：Seedream 的 `image` 是 data URI 数组，Gemini 按顺序放两张图再放提示词，OpenAI 用重复的 `image[]` 字段
- **调整**：亮度、对比度、高光、阴影、饱和度、色温、色调、褪色、锐化、暗角，实时预览
- **滤镜**：鲜明、暖阳、清冷、胶片、日系、复古、浓郁、黑白、褪色黑白，带缩略图和强度
- **裁剪旋转**：自由 / 原比例 / 1:1 / 4:3 / 3:4 / 16:9 / 9:16，旋转 90°、水平翻转；锁定比例时拖四个角
- **相册修图**：编辑页工具栏最后一项，把当前照片交给手机自带的修图应用（小米、华为、OPPO 等的相册编辑器，Google 相册），用它们的 AI 消除、AI 扩图等我们调不到的功能，修完导回来接着编辑（可撤销）。只有一个修图应用直接打开，多个就让用户选（列表里排除我们自己）。导回有三种情况，按顺序判断：对方返回了新照片地址 → 导入；对方写进了我们给的输出文件（`EXTRA_OUTPUT`）→ 导入；对方直接改了输入文件 → 导入；都没有（另存到相册、什么都不说）→ 提示用户在相册里选刚修好的那张。输入、输出是两个文件，输入只给读权限、输出单独授写权限：Markup 拿到写权限会一打开就把文件清空（实测踩到过）
- **撤销 / 重做**（最多 20 步，整图原始像素存在缓存目录）、**按住对比**原图、双指缩放、双击放大
- **保存**到相册「AI修图」文件夹（有透明像素存 PNG，否则 JPEG 95），**分享**给其它 App；也能从别的 App「分享 / 编辑」直接打开
- **界面**：首页浅色（渐变横幅「导入照片」、AI 换脸 / 换装两张大卡片、五列彩色图标的常用工具，含「人像美颜」「证件照」入口：直接打开抠图并选好白底），主色粉红；编辑页深色，突出照片，滑杆拖动时显示数值气泡
- **应用内更新**：启动时每 12 小时读一次 `releases/app-version.json`（gh-proxy、ghfast、jsDelivr、GitHub 原地址同时请求），下载校验 SHA-256、断点续传；下载时可点「后台下载」收起弹窗，由前台服务保活、通知栏显示进度，下完在前台直接弹安装、在后台发通知（下次打开 App 也会提示），中断后保留已下部分，下次续传；安装前核对包名和签名证书必须和已装的一致（防镜像被篡改后诱导安装别的应用），再调系统安装器（代码移植自 TV Player）

编辑时图片最大约 1600 万像素（按可用内存再降），超过的按比例缩小；实时预览在长边 2048 的预览图上算，点 ✓ 时按原图尺寸再算一遍。

## 本地模型

放在仓库 `models/`（来源、许可、输入输出见 `models/README.md`），第一次用到时下载（`ui/ModelDownloads.kt`：进度弹窗可点「后台下载」收起，由前台服务保活、通知栏显示进度，下完发通知；没收起就下完自动接着做；中断后续传，hf-mirror 中途超时先重试一次再换线路），和应用内更新同样走镜像 + 续传 + SHA-256 校验（`core/LocalModels.kt`）：MI-GAN 26.8 MB、Real-ESRGAN 4.6 MB。推理用 ONNX Runtime（安装包里只带 arm64 的库，约 13 MB）；人脸网格用 ML Kit（和人像分割共用运行库）。jsDelivr 不收 20 MB 以上的文件，MI-GAN 只能走 gh-proxy、ghfast 和 GitHub 原地址。

**本机 AI 加速**（`core/Accel.kt`）：每个本地模型第一次使用时，在这台手机上分别用 CPU、XNNPACK（ARM 优化的 CPU 计算）、NNAPI（安卓的 AI 芯片接口，全精度 / 半精度）跑同一份合成输入，结果和 CPU 一致（平均误差 < 值域 2%、最大误差 < 30%）且总耗时（建会话 + 单次 × 每次使用的运行次数）比 CPU 快 10% 以上的才采用，记在设置里（按模型校验值区分）。加速方式加载失败会自动退回 CPU。NNAPI 只能编译固定尺寸，所以变清晰的每块都补齐到 216×216，ArcFace 的批量固定为 1；MI-GAN 输入尺寸每次不同，只比较 CPU 和 XNNPACK。设置 → 本机 AI 加速 可以看每个模型的测速结果、关掉加速、重新测试。模拟器上实测：消除选了 XNNPACK（2.1 秒，CPU 3.5 秒），换脸模型的 XNNPACK 结果和 CPU 不一致被自动排除；真机 AI 芯片的效果要在真机上看。

## 云端 AI 服务设置

设置 → 云端 AI 服务，选火山引擎、Gemini 或 OpenAI 兼容，填 API Key；接口地址、模型可留空用默认：

| | 默认地址 | 默认模型 | 接口 |
|---|---|---|---|
| 火山引擎（默认） | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seedream-4-0-250828` | `/images/generations`（JSON，图片用 data URI，输出尺寸和原图同比例、约 2048²） |
| Gemini | `https://generativelanguage.googleapis.com` | `gemini-2.5-flash-image` | `/v1beta/models/{模型}:generateContent` |
| OpenAI 兼容 | `https://api.openai.com/v1` | `gpt-image-1` | `/images/edits`（multipart） |

中转 / 代理填它的地址即可（Gemini 地址已带 `/v1beta` 之类版本号时不再追加）。照片缩到长边 1536 再上传。Key 只存本机，应用关闭了系统备份。

## 构建与测试

需要 JDK 17+、Gradle 9.x、Android SDK 35（`local.properties` 的 `sdk.dir` 指向 SDK，不提交）。`gradle.properties` 里写了本机代理 `127.0.0.1:7890`，没有代理的环境删掉 `systemProp.*` 几行。

```bash
gradle assembleDebug        # app/build/outputs/apk/debug/app-debug.apk
gradle testDebugUnitTest    # JVM 单测：调整、增强、美颜、消除填充、导向滤波、云端接口请求与解析、更新镜像
```

单测只覆盖纯计算和接口协议（`core/` 里不依赖 android.graphics 的部分）；界面、人像分割、相册读写要在真机或模拟器上验证。

## 发版

和 TV Player 相同：APK 提交在仓库的 `releases/` 里，`releases/app-version.json` 是应用内更新读的版本说明。

```bash
scripts/release.sh 2 1.0.1 "这一版的更新说明"
```

脚本依次：用 `-PappVersionCode / -PappVersionName` 打 release 包（R8 混淆 + 资源压缩）→ zipalign → 用本机 `~/.android/debug.keystore` 签名（关掉 v1 和 v4）→ 打印证书 SHA-256（和上一版核对）→ 生成 `releases/app-version.json` → `releases/` 只留最近 5 个 APK。然后提交（信息格式 `AI Photo 1.0.1: 改了什么`）并推送到 `main`，手机上「检查更新」就能收到。

签名证书就是本机的 debug.keystore：换电脑发版要带上这个文件，否则新包签名不同、覆盖安装会失败。

## 验证情况

在 Android 15 模拟器（Pixel 6 尺寸）上实际操作过：首页 → 系统照片选择器 → 编辑页；智能增强；人像抠图的虚化、白底并保存（相册里 1600×2400 的 JPEG）；快速消除；裁剪 1:1 + 旋转 + 拖角后保存（1301×1301）；滤镜；调整；撤销；设置页填写。AI 修图和 AI 消除对着本机模拟的 Gemini / OpenAI 接口验证了请求格式（地址、Key 请求头、图片、提示词、multipart 蒙版）、结果贴回和出错提示。

1.0.13：换脸加「提供脸的人戴眼镜时：去掉眼镜 / 保留眼镜」。电脑上用 3 个戴眼镜的虚构人脸换到 4 张脸上：默认会多一副半透明眼镜框；「去掉眼镜」后三个人都干净（和原特征相似度 0.96～0.99），「保留眼镜」换出完整的眼镜；86 个不戴眼镜的人被「去掉眼镜」处理后平均相似度 0.997。试过但没采用：在照片上抹眼镜再算特征（人脸解析找眼镜 + MI-GAN 补图或平滑填充），补出的眼周有污迹、像墨镜，反而更容易画出眼镜。模拟器上「去掉眼镜」实测干净。同一版修了内存：GFPGAN 半精度版在安卓上跑一次要占 1.4 GB（电脑上只有 0.8 GB），2.5 GB 的模拟器上连续换第二次脸时 App 被系统杀掉（占用 1.8 GB）；换成只量化权重的 INT8（88 MB，和原版差 53 dB），再给两个大模型关掉内存池，各步骤峰值 ArcFace 329 / 换脸 857 / 修复 746 MB。

1.0.12：换脸模型换成 HyperSwap 1c（只量化权重的 INT8，和原版差 51 dB，202 MB；关掉内存复用规划后跑一次的峰值 1093 → 705 MB）。App 的 Kotlin 流程导出的结果和 Python 试验一致；模拟器上全新安装后由 App 从 hf-mirror 下载换脸模型、首次换脸（含人脸特征测速）共 134 秒，App 没被杀，女→男没有胡子痕迹。

1.0.11：高清换脸加 GFPGAN 人脸修复、整块贴回。电脑上用两张测试照片互换对比了四种做法（现在的、整块贴回不修复、加 GFPGAN、加 GPEN-256），GFPGAN 最自然：眼睛、牙齿干净，胡子痕迹基本消失；GPEN 只有 76 MB 但残留噪点和胡子阴影，而且只许非商业使用。GFPGAN 半精度和原版差 62 dB；INT8 反而 273 MB、30 dB，不采用。App 的 Kotlin 流程导出的结果和 Python 试验一致。GFPGAN 在 2.5 GB 内存的模拟器上测速时会被系统杀掉，改成不测速、关掉图优化（会话内存峰值 1059 → 801 MB）；首次使用时 inswapper 的测速紧接着 GFPGAN 仍会被杀（占用 1.6 GB），inswapper 也改成不测速后正常。修复窗口反算回原图、并进换脸的裁剪块，避免歪头时窗口超出裁剪块（35° 歪头照片上旧版没有可见接缝，但送进 GFPGAN 的边缘是复制出来的像素）。正式包全新安装后由 App 从 hf-mirror 下载三个模型（约 2 分钟）、换脸整条走通。

1.0.10：高清换脸换成 INT8 量化版（下载 451 MB → 221 MB），模拟器上人脸特征 377 → 84 毫秒、换脸 11.5 → 1.1 秒；整条流程换出的脸像提供者的程度 0.909 → 0.900（电脑上两人互换），App 自己的 Kotlin 流程和原模型的结果脸部平均亮度差 3.4。正式包全新安装后由 App 自己从 hf-mirror 下载两个模型（模拟器直连约 2.5 分钟）、校验、测速、换脸整条走通；升级时启动就删掉被取代的旧模型（含校验标记和下载残留，单测保证被取代的文件名不是在用的）。

没有验证的：本地换脸在东亚人脸上的效果（测试照片不够）；模型从 GitHub 镜像真实下载（要推送后才有）；真实的火山引擎 / Gemini / OpenAI 服务（没有 Key）及其实际修图、换脸、换装效果（服务可能拒绝换脸这类请求）；真机；Android 8～9 的存相册（走旧的存储权限路径）；应用内更新的下载安装（要等第一版推送后才有 `app-version.json`）。

已知局限：人像分割是 ML Kit 的自拍模型（输入 256×256），人贴着墙、有影子时，影子可能被当成人的一部分（换纯色底时看得出来）；需要更精细的换底可以用「AI 修图」描述。
